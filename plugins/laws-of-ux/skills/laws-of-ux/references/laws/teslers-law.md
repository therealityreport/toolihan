# Tesler's Law (Conservation of Complexity)

**Principle · weight 2 · tier b · SCORED · owner: Forms**

- **Definition / why it matters:** Every system has irreducible complexity; the question is who
  absorbs it — the system or the user. Push it onto the system.
- **Applies when:** there are forms/flows where the system could compute or default what it
  currently asks.
- **Adherence signals:** smart defaults; autofill; values computed instead of asked; progressive
  disclosure of advanced options; wizards that handle complexity for the user.
- **Violation signals:** every field required with no defaults; asking for data the system
  already has or could derive; exposing raw configuration complexity to the user. Grep `required`
  density, absence of `defaultValue`/defaults.
- **Confidence:** b.
- **Example fix:** pre-fill known values; compute totals/derived fields; hide advanced options
  behind "Advanced".
